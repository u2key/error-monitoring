# error-monitoring

三重化(TMR)したデザインを FPGA に実装して放射線試験などを行うときに、三重化フリップフロップの
不一致を別の FPGA(テスター)から読み出して数えるための回路とホストソフトです。

```
 被測定 FPGA                              テスター FPGA                     ホスト PC
┌───────────────────────┐ design_clk  ┌─────────────────────┐ UART ┌────────────┐
│ 三重化デザイン         │ ◀────────── │ em_detector_top      │ ◀──▶ │ em_host.py │
│  (--tmr --probe)       │ read_clk    │  クロック生成         │      │  比の指示    │
│   TMRDFF_A/_B/_C       │ ◀────────── │  走査・判定・カウンタ  │      │  校正       │
│        ↓               │ addr_a/b/c  │  入力タイミング調整    │      │  時間管理    │
│ tmrdff_readout         │ ◀────────── │                     │      │  再構成      │
│  (系統ごとにアドレス)   │ lane,echo   │                     │      │  CSV 保存    │
│                        │ ──────────▶ │                     │      │            │
└───────────────────────┘             └─────────────────────┘      └─────┬──────┘
          ▲                                                              │
          └───────────────── quartus_pgm (USB-Blaster) で再構成 ◀─────────┘
```

## クロック

- **テスターが両方のクロックを作ります。** 読み出しクロック `read_clk` は論理合成の最大動作周波数以下で切りのいい値にします。
- **設計クロック** = `read_clk` / R。比 R はホストが UART で指示します(`--ratio`、`[scan] ratio`)。R は2以上で、`GUARD` より大きい値です。
- **被測定側の `read_clk`** は反転して出力します。アドレスが変わってから半周期後に取り込むためです。
- **`sample_clk`** は `read_clk` の整数倍で、同じ PLL から作ります。入力線の遅延調整に使います(後述)。

## 判定のしかた

- フリップフロップの出力は、generate-tmr-vhdl の `--probe` で `TMRDFF_A/_B/_C` としてトップに出ます。
- ワード k は TMRDFF のビット `k*LANES` 〜 `k*LANES+LANES-1` です。
- **窓を2回読みます。** 1周期の最後の W サイクルで W 個のアドレスを読み、次の周期に同じアドレスを同じ位相で読み直してから、次の窓へ進みます。
  W = min(アドレス数, R − `GUARD`, `WMAX`) です。

  ```
  R = 8, GUARD = 1:  [0 1 .. 6] 設計クロック [0 1 .. 6] 設計クロック [7 8 .. 13] 設計クロック [7 8 .. 13] ...
  ```

  待ち時間はありません。読み出しはパイプライン化されていて、アドレスにタグを付けて流し、戻ってきたデータと照合します。
  2回の読み出しの間には必ず設計クロックの立ち上がりが1回入ります。
- ビットごとに A/B/C がそろっていなければ、その読み出しはエラーです。
  - 片方の読み出しだけエラー → **フリップフロップのエラー**。数えて報告し、走査を続けます。
  - 同じビットが両方の読み出しでエラー → **構成回路のエラー**。数えて報告し、走査を止めます。ホストが再構成して、走査を再開します。
- **場所ごとに数えます。** テスター内にアドレスごとのカウンタ(フリップフロップエラー16ビット、構成エラー8ビット、飽和)があり、ホストはイベントからビットごと・レジスタごとに集計します。

### `GUARD`

設計クロックの直後の読み出しは、設計の出力が変わってから半周期しかありません。そこで、既定の `GUARD=1` では各周期の最初の1サイクルを読みません。
R=8 なら1周期に7アドレスです。タイミングに余裕があることを実機で確認できたら、`GUARD=0` で8アドレスにできます。

### 走査モード

| モード | 指定 | 内容 |
|---|---|---|
| `sweep` | `--mode sweep` | 全アドレスをまんべんなく走査する |
| `fixed` | `--mode fixed --addr N` | 1アドレスを読み続ける |
| `list` | `--mode list --list-file F` | 指定したアドレスだけを走査する(既定で最大4096個) |

リストファイルは、1行に1項目(アドレス、`bit N`、レジスタ名)か、以前の試験の `counters.csv`(エラーのあったアドレスを走査)です。
レジスタ名には `[layout] map` が必要です。走査中のモード変更はできません。

### フリップフロップエラーの検出率と補正

投票つきの三重化フリップフロップは、1つのレプリカが反転しても次の設計クロックで直します。
位相 k(0始まり)の読み出しは設計クロックの (k + 0.5) サイクル後に値を取り込むので、周期のうちの (k + 0.5) / R の間に起きた反転が見えます。
窓は1回の走査のうち2周期分読むので、窓の数を nw として、検出率は次のとおりです。

    P = ((k + 0.5) / R) / nw

送信回路(687,208 ビット、4並列で 171,802 アドレス)を R=8、`GUARD=1` で走査すると、nw = 24,543、平均の検出率は約 2.3×10⁻⁵、1回の走査は 392,688 読み出しサイクルです。

観測した反転ごとに 1/P を足した値を推定値として `summary.csv`(合計、95% 範囲、1秒あたり)と `per_bit.csv` に出します。リストのモードでは、リストにあるアドレスだけの推定値です。

- **前提:** 反転は次の設計クロックまで続き、時間的に一様に起きるとしています。ボード間の配線遅延の差は無視しています。再構成中は数えません。
- **精度:** 観測数が少ないと推定の幅が大きくなります。観測0回なら上限だけが意味を持ちます。
- **誤判定:** 同じビットが続く2周期の両方でたまたま反転すると、構成エラーと判定されます。反転率が低ければ無視できます。

## タイミングの調整

- **3対のアドレス線:** A/B/C それぞれにアドレス線、アドレスレジスタ、マルチプレクサがあります。1系統の読み出し回路が壊れても3系統の不一致として見えます。
- **エコー:** `tmrdff_readout` は、読んだアドレスのパリティを系統ごとに `echo_x` で返します。テスターは要求したアドレスのパリティと比べて、ずれを系統ごとに数えます(`STATUS` の値、`summary.csv` の `echo_bad_*`、`events.csv` の `echo_bad`)。
- **リンク喪失:** `2**LINK_LOG` 回の読み出しのうち4分の1以上でエコーが違うと、リンク喪失として報告します(`[reconfigure] link_loss_is_config` で構成エラーとして扱えます)。1アドレス固定のモードでは、エコーが正しい値に張り付くと見つかりません。
- **校正:** アドレス `2**ADDR_WIDTH-1` は全ビット1、`2**ADDR_WIDTH-2` は全ビット0を返します。ホストはレイテンシとタップの組み合わせごとに、この2つを疑似乱数の順に読むトレーニングを実行し、入力線ごとの合否を集めます。
  すべての線に共通のレイテンシと、線ごとの最長の合格範囲の中央のタップを選びます(`calib.csv`)。試験の開始時と再構成のあとに行います。
- **入力遅延:** 各入力線は `sample_clk` のシフトレジスタを通ります。`sample_clk` が `read_clk` の OS 倍なら、1タップは `read_clk` の 1/OS 周期です。

### オーバーサンプリングとのトレードオフ

`sample_clk` の上限で `read_clk` の上限が決まります。たとえば `sample_clk` が 200 MHz までなら、OS=4 で `read_clk` は 50 MHz までです。
`TAPS` は OS の2倍以上にしてください(線間のずれが大きいなら3倍)。OS=1(`sample_clk` = `read_clk`)にすると、1サイクル単位の調整だけになる代わりに `read_clk` を最も速くできます。

## 被測定 FPGA 側

1. デザインを generate-tmr-vhdl で `--tmr --probe` 付きで変換します(`--light` はシミュレーション用なので実機には使いません)。
   トップの `<top>.tmrdff.map` の1行目に、1系統あたりのビット数(WIDTH)が出ます。
2. ボードのトップで、三重化デザインと `tmrdff_readout` をつなぎます。デザインのクロックには `gpio_design_clk` を使います。

```vhdl
u_ro : entity work.tmrdff_readout
  generic map (WIDTH => 687208, LANES => 4, ADDR_WIDTH => 18)
  port map (read_clk => gpio_read_clk, tmrdff_a => tmrdff_a, tmrdff_b => tmrdff_b, tmrdff_c => tmrdff_c,
            addr_a => gpio_addr_a, addr_b => gpio_addr_b, addr_c => gpio_addr_c,
            lane_a => gpio_lane_a, lane_b => gpio_lane_b, lane_c => gpio_lane_c,
            echo_a => gpio_echo_a, echo_b => gpio_echo_b, echo_c => gpio_echo_c);
```

`ceil(WIDTH / LANES)` は `2**ADDR_WIDTH - 2` 以下にします(上の2つはトレーニング用です)。

## テスター FPGA 側

`em_detector_top` をボードのトップにし、ピンを割り当てます。`read_clk` と `sample_clk` は PLL から与えます。UART も `read_clk` で動きます。

| ジェネリック | 意味 | 既定 |
|---|---|---|
| `CLK_HZ` | `read_clk` の周波数。UART の分周とホストの計算に使う | 50 MHz |
| `BAUD` | UART の速度 | 115200 |
| `LANES` | 並列数(被測定側と同じ値) | 4 |
| `ADDR_WIDTH` | アドレス幅(被測定側と同じ値) | 18 |
| `NUM_ADDR` | アドレス数 = `ceil(WIDTH / LANES)` | 171802 |
| `GUARD` | 設計クロックの直後に読まないサイクル数 | 1 |
| `WMAX` | 窓の最大アドレス数 | 256 |
| `TAPS` | 入力遅延のタップ数 | 8 |
| `LMAX` | 読み出しレイテンシの上限 | 32 |
| `LIST_BITS` | リストの深さ `2**LIST_BITS`(`ADDR_WIDTH` 以下) | 12 |
| `SWEEP_LOG` | 走査 `2**SWEEP_LOG` 回ごとに走査数を報告 | 8 |
| `FIFO_LOG` | イベント FIFO の深さ `2**FIFO_LOG` | 6 |
| `TRAIN_RUN` | トレーニング1回で比べる読み出しの回数 | 256 |
| `LINK_LOG` | リンクの判定に使う読み出し回数 `2**LINK_LOG` | 16 |

### ピン数(LANES=4、ADDR_WIDTH=18 のとき)

| 信号 | 本数 | 向き(テスターから見て) |
|---|---|---|
| `dut_lane_a/b/c` | 12 | 入力 |
| `dut_echo_a/b/c` | 3 | 入力 |
| `dut_addr_a/b/c` | 54 | 出力 |
| `dut_design_clk`, `dut_read_clk` | 2 | 出力 |
| 合計 | 71 | GPIO 2本(約72本)に収まります |

### 実機で確認が必要なこと

この環境には Quartus がなく、論理合成と実機試験はしていません。

- **読み出しクロックの上限:** 被測定側のマルチプレクサは 171,802 ワードから選ぶ深さがあり、1サイクルで終わらないと `read_clk` の上限を決めてしまいます。合成結果を見て、周波数を決めてください。
- **メモリ:** カウンタ RAM は 171,802 × 24 ビット(約 4.1 Mbit)です。テスター基板の FPGA に入るか確認してください。入らなければカウンタの幅を減らします(イベントは CSV に残ります)。
- **クロック出力:** `dut_read_clk` は論理で反転しているだけです。基板の PLL で位相をずらした出力に置き換えられるなら、そのほうが安定します。
- **`sample_clk` と `read_clk` の間のタイミング制約:** 同じ PLL から作った同期クロックとして制約してください。

## ホスト PC

```
cd host
cp config.example.ini config.ini     # ポート、map、比、quartus_pgm のコマンドを設定
python3 em_host.py config.ini --ratio 8 --duration 3600
python3 em_host.py config.ini --ratio 8 --mode fixed --addr 1234
python3 em_host.py config.ini --ratio 8 --mode list --list-file ../results/20261104-120000/counters.csv
```

- **前提:** pyserial が必要です。
- **試験時間:** ホストが管理します(`[test] duration_s`)。`count_downtime = no` なら、再構成で止まっていた時間を除いて走査時間が `duration_s` に達するまで続けます。
- **構成エラーのとき:** 走査を止めて `[reconfigure] command` を実行し、`settle_s` 待って、校正し直して(`[scan] recalibrate`)、走査を開始します。

### 出力(`[output] dir/<日時>/`)

| ファイル | 内容 |
|---|---|
| `events.csv` | エラー1ビットごとに1行。`time_s, wall_time, kind (soft/config/link_loss), sweep, address, lane, bit, register, read (1/2/both), replicas (ずれた系統), echo_bad (エコーが違った系統と読み出し)` |
| `reconfig.csv` | 再構成ごとに1行。`n, trigger, start_s, end_s, duration_s, return_code, output` |
| `calib.csv` | 校正ごと・入力線ごとに1行。`n, time_s, latency, line, name, tap, eye_taps` |
| `counters.csv` | テスターのアドレスごとのカウンタ(終了時のダンプ)。`address, bit_lo, bit_hi, registers, soft, config` |
| `counters_history.csv` | `dump_interval_s` を設定したときの途中のダンプ |
| `per_bit.csv` | ビットごとの集計。`bit, address, lane, register, soft, config, visibility, soft_estimated` |
| `summary.csv` | 設定(モード、比、窓)、時間、合計、エコーのずれ、FIFO あふれの有無、平均検出率(`soft_visibility_mean`)と補正後の推定値(`soft_estimated`、`_low95`、`_high95`、`_per_s`) |

## プロトコル

- **ホスト → テスター(コマンド):**
  `S` 開始、`P` 停止、`R` 構成エラーの停止からの再開、`C` カウンタのクリア、`D` カウンタのダンプ、`I` 情報、`?` 状態、`T` トレーニング1回、
  `F`+3バイト 比、`L`+1バイト レイテンシ、`A`+線+タップ 入力遅延(線 0xFF は全線)、`M`+1バイト モード、`U`+個数2バイト+アドレス リスト。
  `F`、`L`、`A`、`M`、`C`、`T` は走査中なら NACK を返します。
- **テスター → ホスト(フレーム):** `0xA5, type, length, payload, checksum`。checksum は type・length・payload の XOR です。
  各フレームの内容は `hdl/em_host_if.vhd` の冒頭を参照してください。

## 検証

```
sim/run_sim.sh                         # Questa。GEN_TMR に generate-tmr-vhdl の場所
cd host && python3 -m unittest test_em_host
```

**システム・テストベンチ**

小さな三重化デザイン(`sim/dut/areset.vhd` を `--tmr --light --probe` で変換、TMRDFF 37ビット、4並列で10アドレス)と、
読み出し回路、テスター、UART のホストモデルをつないで、次を確かめます。入力線ごとに違う遅延(2〜14 ns、`read_clk` 周期 20 ns)を入れています。

1. INFO に応答する。比のコマンドで設計クロックの周期が変わる。不正な値と走査中の変更は NACK になる。
2. 校正前は、エコーがずれとして数えられる。
3. 校正でレイテンシとタップが決まり、そのあとの故障なしの走査ではエラーもエコーのずれも出ない。
4. **ランダムな時刻の反転(次の設計クロックまで持続):** 検出数が検出率の式と合い(4σ以内)、場所が正しく、構成エラーとは判定されない。
5. **固定した反転:** 構成エラーとして正しい場所で報告され、走査が止まる。解除と再開のあとはエラーが出ない。
6. カウンタのダンプが、受信したイベントと一致する。
7. **リスト・固定モード:** リストにあるアドレスだけを読み、検出数が式と合う。リストにないビットの反転は報告されない。
8. 読み出し回路のクロックを止めるとリンク喪失が報告され、戻すと復帰が報告される。

結果の例(反転の検出数 / 式の期待値): 走査 193 / 206(P=0.344)、リスト 164 / 163(P=0.813)、固定 75 / 75(P=0.938)。

**ホスト側のテスト**

テスターのモデルを相手に、校正の選び方、検出率の計算、リストファイルの読み方、FF エラー・構成エラー・リンク喪失を受けたときの流れ(再構成コマンドの実行、校正、走査の開始)と、各 CSV の内容を確かめます。
